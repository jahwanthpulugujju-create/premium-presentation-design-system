# Design reference method

PPD uses references to learn design principles, not to copy another presentation's distinctive expression.

## What to capture from a reference

For every approved reference, record:

- Source URL, creator, publication date and usage/permission status.
- Presentation context and intended audience, when known.
- Grid, margins and alignment logic.
- Typography hierarchy and text density.
- Use of contrast, colour and whitespace.
- Image selection, crop, scale and placement.
- Data and diagram treatment.
- Visual rhythm across adjacent slides.
- The specific communication problem the composition solves.

## What not to store as a reusable rule

- A direct copy of a slide or complete deck.
- A brand logo or proprietary asset without permission.
- A distinctive illustration or layout copied as a fixed template.
- Images without a recorded source and rights status.

## Reference-to-principle workflow

1. Curate a diverse set of legally usable references.
2. Annotate the design decisions that make each reference effective.
3. Extract abstract principles, such as hierarchy, pacing or contrast.
4. Apply those principles to new content with an independently developed composition.
5. Review the result for accidental similarity and visual clichés.

A reference is an input to design reasoning, not a source file to reproduce.
